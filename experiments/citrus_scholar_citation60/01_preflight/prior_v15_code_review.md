## 1. 最终产品定义

**CitrusScholar 是面向柑橘及相关农业科研的多来源、证据可追溯、文件可交付的科研智能工作台。**

它是单 General Agent + 17 个受环境和任务约束的工具 + 本地 BM25/Dense 混合检索与重排 + Web 检索与公开论文核验 + 表格数据审查与科研成果导出 + 多用户账号资料库的模块化单体 Web 应用。

### 用户可完成的科研工作

1. 带来源的领域科研问答：公共柑橘文献、方法、UCR 记录、中文品种志、翻译文献与互联网材料。
2. 本地原文阅读、文献与 DOI 登记信息核验、论文解读、补充材料查询。
3. 上传 CSV/TSV/Excel/PDF/Word 后开展表结构检查、规则化数据审查，导出标记与批注的 Excel，提供问题清单、规则状态和覆盖概览。
4. 导出文献证据表、论文解读、实验设计、科研笔记、语料缺口报告及 SVG 科研示意。
5. 账号隔离的会话、上传文件、生成文件及显式科研笔记管理，后台账号管理与 ONNX 推理设备切换。

### 科研边界

- 模型结论需要人工核实；工具成功不等于答案所有事实已证真。
- 数据审查返回**复核线索**，不是造假检测或统计结论。
- 病害图片属于视觉模型辅助筛查，非临床/实验室确诊。
- 上传文件默认不导入共享语料；普通聊天不自动形成长期记忆。
- 五个清洗语料中的 `cqa_methods` 允许任何已登录账号访问；如果有私有实验室 SOP，必须单独审查数据归属和权限，不能直接混入这一公共库。

### 实际发现的代码层问题（优先修复）

**SSE 最终正文与已保存正文可能不一致。**

在 `01_src/src/graph/general_agent_graph.py`，模型原始 `answer` 在约 1590 / 1598 / 1675 行先通过 `emit_text(answer)` 发送。随后 1730 行以后才为失败的必需工具增加说明、给最终答案追加 `_append_verified_artifact_links(...)`、展开图件并清理内部标识。`01_src/web/assets/app.js` 中的 `text` 事件只负责追加 `data.content`，`done` 事件没有用服务器最终 `answer` 替换界面全文。

**影响：** 本轮可见回答可能缺少后补的已验证下载链接或必需步骤失败提示，刷新历史后才看到后处理版本。该现象来自静态调用链，尚待真实端到端复现。

**建议修复：** 记录已发出的回答；最终后处理之后比较。若只是追加内容，增量发送后缀；若发生前缀或中间替换，发出已有的 `text_reset` 后重新发送最终版本；若此前没有发过回答，则直接发送最终版本。

已制作只针对上述位置的安全本地修复脚本 `citrusscholar_v15_sse_hotfix.py`。五个锚点已与 GitHub 指定版本逐一对照，均恰好匹配一次。**脚本未在用户实际工作区执行，亦未发布。**

## 6. 最终判断

CitrusScholar v15 已经是一款有明确科研工作流和多用户交付能力的**可试用科研软件系统**，不只是演示。它的主要工程价值在于“能够追溯真正做过的操作，并校验交付文件”。当前不宜宣称为“完成所有公网安全、持续交付和学术有效性验证的成熟平台”。先完成 TLS/权限审计和 SSE 修复，再冻结可追溯的候选发布版本，才是合理的最终交付标准。
