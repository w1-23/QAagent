# QA60 Gold 逆向生成与人工审核规程

版本：1.0  
状态：`PROPOSED_PENDING_PI_APPROVAL`  
适用范围：`E01_QA60_EGTS` 及共享同一 QA Gold 的输入构建  
核心原则：**机器从冻结语料抽取证据并起草，领域专家独立核验并仲裁，最终 Gold 不由生成模型自行批准。**

## 1. 为什么可以采用逆向生成

从冻结语料出发可以降低逐题人工翻找原文的成本，并保证每个 Gold 事实都有明确来源、版本和定位。该方法适合生成：

1. 单来源事实题：L、V、W、P。
2. 多来源综合题：X，由两个或以上来源的 Gold Claim 组合而成。
3. 限定条件下的不可答题：N，但必须预先写明允许的证据范围和“缺失证明”，不能由生成模型自行宣布“文献没有”。

逆向生成不等于让模型出题后直接当 Gold。容易出现的偏差包括：

1. 问题和答案共用同一句原文，造成词汇重合和题目过易。
2. 只抽容易定位的数字，遗漏真正需要证据综合的问题。
3. 生成模型把摘要、推断或常识误当成原文事实。
4. 同一证据被拆成多个“独立”小题，虚增样本独立性。
5. N 类题的“不可回答”只是检索失败，不是来源范围内确实没有证据。
6. 使用 B0/B1/B2 的回答反推 Gold，形成循环验证。

因此采用“候选生成 + 双人核验 + 仲裁 + 锁题”的混合流程。

## 2. 数据对象

### 2.1 Evidence Unit（证据单元）

一条可直接回指来源的原子证据，不等同于一段任意文本。字段至少包括：

| 字段 | 含义 |
|---|---|
| `evidence_unit_id` | 稳定 ID，如 `EU_D01_P04_S2_01` |
| `source_id` | D01–D11、UCR、CNVAR 等 |
| `document_version` / `snapshot_id` | PDF 版本、网页抓取时点、索引 generation |
| `source_sha256` | 来源文件或冻结 snapshot 的 SHA |
| `locator` | 页码/章节/图号/表号/单元格/UCR record ID/URL 抓取时间 |
| `evidence_excerpt_short` | 为内部审核保留的短引文；公开包受版权限制 |
| `evidence_summary_internal` | 对证据内容的中性摘要 |
| `fact_type` | 事实、方法、材料、数字、比较、限制、推断 |
| `material_or_dataset` | 涉及的品种、处理、样本、数据集或实验条件 |
| `scope_limit` | 该证据不能外推到什么对象或结论 |
| `valid_as_of_utc` | 对网页、更正、DOI、数据库状态的有效时点 |
| `generated_by` | 抽取工具/模型/人工 |
| `generation_method` | 规则、模型 ID、prompt SHA、人工来源 |
| `review_status` | `DRAFT/ACCEPTED/REJECTED/NEEDS_ARBITRATION` |

### 2.2 Gold Claim（Gold 原子声明）

一条可独立评分的声明，是最终原子槽位的来源。每个 Gold Claim 必须：

1. 指向一个或多个 Evidence Unit。
2. 能被专家判断为正确/不正确。
3. 只表达一个可核验事实或关系。
4. 带可接受同义表述和致命错误。
5. 明确适用的材料、处理、来源范围和时点。

一个 Evidence Unit 可以支撑一个或多个 Gold Claim；一个 Gold Claim 也可以需要多个 Evidence Unit 共同支持，但必须显式记录依赖。

### 2.3 Gold Bundle（Gold 组合）

一个 Gold Bundle 是同一相关问题所需 Gold Claim 的集合：

```text
1 个 question_id
  -> 1–5 个 atomic Gold Claims
  -> 1–N 个 Evidence Units
  -> 1–N 个 source_ids
```

规则：

1. L/V/W/P 通常使用一个来源的 1–5 个原子 Claim。
2. X 必须至少连接两个独立来源，并包含真正的跨来源比较、组合或冲突识别。
3. 如果 X 题任意一个来源单独就足以完成全部核心槽位，则该题不合格，必须在锁定前修订或改分层。
4. 同一来源的多个近义事实不能伪装成多个独立题目。
5. 每题 2–5 个核心原子槽位；不足 2 个或超过 5 个需专家写理由。

### 2.4 一个或多个 Gold 构成一个问题

采用以下唯一映射：

```text
question_id -> gold_bundle_id -> [gold_claim_id, ...] -> [evidence_unit_id, ...]
```

最终评分仍以 `question_id × condition` 为单位，内部按 Gold Claim/原子槽位计算正确性。不能把一个 Bundle 的多个证据拆成多个独立统计样本。

## 3. 生成流程

### 3.1 Step G-A：冻结语料

1. 只使用已核验许可和已登记 SHA 的来源。
2. 对每篇 PDF、UCR 记录、网页 snapshot、CNVAR 条目建立 `source_id + version + SHA + locator`。
3. 建立冻结索引 generation 和文档文本快照。
4. 未授权或无法访问的来源不能进入 Gold。
5. 生成阶段只读取冻结语料，不读取任何 B0/B1/B2 正式回答、评分或人工讨论。

### 3.2 Step G-B：抽取 Evidence Unit

1. 按文献/记录抽取摘要、方法、材料、结果表、图注、限制段和补充材料。
2. 对表格必须记录工作表、行、列、单元格或表号。
3. 对网页必须记录 URL、抓取 UTC、页面标题、版本和 SHA。
4. 对 UCR 记录必须记录 record ID。
5. 抽取器不得补全原文没有的数值、单位、品种、处理或结论。
6. 每条 Evidence Unit 进入候选表，不直接进入锁定 Gold。

### 3.3 Step G-C：形成 Gold Claim

1. 将证据拆成一个可独立核验的原子声明。
2. 记录 `expected_answer`、`acceptable_variants`、`fatal_errors` 和 `scope_limit`。
3. 对数值保留单位、统计量、样本量和比较对象。
4. 对推断标注“作者推断”“综述观点”或“原始实验证据”，不能混写。
5. 无法确定唯一答案的证据标 `REJECTED` 或转人工讨论，不强行生成。

### 3.4 Step G-D：组合 Gold Bundle

1. 按来源分层和覆盖槽位挑选 1–5 个 Claim。
2. X 题至少连接两个独立来源，并写明两个来源之间的共同点、差异或组合关系。
3. P 题的 Bundle 只能使用当前轮附件，不得暗用本地索引。
4. W 题的 Bundle 必须冻结网页/DOI/更正时点。
5. V 题的 Bundle 必须来自具体 UCR record 或已授权 CNVAR entry。
6. N 题的 Bundle 必须写明限定范围、可查证据和不可得理由；不能只写“检索无结果”。

### 3.5 Step G-E：生成问题候选

使用独立生成阶段，被允许读取 Bundle 和 Evidence Unit，但不得读取任何基线回答：

1. 生成中文问题草案，避免直接复制证据原句。
2. 问题不得包含答案、答案选项、槽位顺序提示或“请列出 N 点”之外的答案结构泄漏。
3. 生成 1 个主问题和必要的中性澄清；不得生成依赖 Gold 内部字段名的题。
4. 对多来源题必须让用户明确需要综合两个来源，但不能告诉用户具体答案。
5. 生成器只能产生候选，不能写 `adjudicated=YES` 或 `locked=YES`。

### 3.6 Step G-F：机器预检

在交给专家前自动检查：

1. `source_id`、`source_sha256`、`locator` 是否存在且可回指。
2. 每题是否有 2–5 个核心 Claim。
3. Claim 是否存在重复或同义重复。
4. 问题是否包含 Gold 原句过长复制、答案数字或 Slot 字段。
5. X 题是否确实有两个来源；单来源能否覆盖全部核心 Claim。
6. P 题是否只引用附件来源。
7. N 题是否有“允许证据范围 + 缺失理由 + 正确拒答示例”。
8. 60 题分层、难度、来源和 query type 分布是否满足预注册方案。
9. 是否与 pilot12 或已泄漏的调试题重复。
10. 是否出现未授权来源、私有数据或敏感信息。

机器预检通过只表示“可送人工审核”，不表示 Gold 正确。

### 3.7 Step G-G：双人独立审核

两位领域专家分别审核同一候选包，彼此不可见对方的结论。每人对每个 Bundle 判断：

1. 问题是否明确且符合预注册任务类型。
2. 核心 Claim 是否完整，是否应拆成更多槽位。
3. 每个 Claim 是否被证据真正支持。
4. 可接受变体是否合理。
5. 致命错误/外推边界是否充分。
6. 来源范围和材料/时点是否明确。
7. X 是否确实需要跨来源。
8. N 是否确实不可由授权范围回答。
9. 问题是否存在答案泄漏或词汇过强提示。
10. 是否应保留、修订或拒绝。

原始审核分别保存，不能覆盖。

### 3.8 Step G-H：仲裁与锁题

1. 两人一致接受且全部字段完整：可进入候选锁定包。
2. 两人分歧：由第三人/预设负责人仲裁，记录原始分歧、理由和决定。
3. 任何来源不可回指、Claim 无法核验、X 不跨来源、N 缺失证明不足：拒绝或修订。
4. 仲裁后生成 `qa60_LOCKED.csv` 和 `qa_gold_atomic_slots_LOCKED.csv`。
5. 同时生成 Bundle 映射、审核台账、来源 SHA 和 `locked_manifest.json`。
6. 锁定后不得因模型答错而删题；只能以新协议版本和变更记录处理。

## 4. N 类不可回答题的特别规则

逆向生成不能证明“论文没有某数据”，只能证明“在锁定语料和指定范围中没有找到允许用于回答的证据”。因此每条 N 题必须有：

1. 允许检索的来源集合。
2. 实际核验的文档、章节、表格和时点。
3. 缺失的性质：未报告、未授权、未纳入本研究、特定字段不存在或问题超出可回答范围。
4. 允许的正确拒答表达。
5. 禁止的错误外推。
6. 人工专家确认的“不能回答”理由。

如果只能证明“当前检索器没找到”，不能自动升级为 N 类 Gold。

## 5. 防止循环和泄漏

1. Gold 生成器不得读取 B0/B1/B2 回答、run JSON、评分或 error_type。
2. 问题改写模型不得看见最终评分和人工争议。
3. B1/B2 运行时不得拿到候选 Gold、评分表或内部 prompt。
4. 公开题面可以进行语法和可读性编辑，但锁定后不得改写答案相关字段。
5. 生成器、抽取器、改题器和模型配置都进入脚本/配置 SHA。
6. 若使用外部模型生成或审核，必须确认数据外发允许；不得把受限全文、私有 SOP、密钥或账号信息发送出去。
7. 研究团队应当保留自动生成的原始候选和人工拒绝项，不能只保留最终采用的 60 题。

## 7. 专家最少需要人工确认的内容

机器可以完成证据抽取、候选拆解、题目起草、去重、格式和可回指性检查，但不能替代以下人工判断：

1. 问题是否有真实领域意义。
2. 答案是否正确且没有把作者推断写成实验事实。
3. 原子槽位是否既不缺失又不过度拆分。
4. X 题是否真的需要多个来源。
5. N 题是否确实不能从授权语料回答。
6. 可接受答案变体和致命错误是否合理。
7. 冲突意见的最终仲裁。
8. 对最终 60 题和 Gold 的签署批准。

## 8. 完成标准

只有同时满足以下条件，G06 才能由人工标记为 `PASS`：

1. 60 个 question_id 均映射到 Gold Bundle。
2. 每题 2–5 个核心原子 Claim。
3. 每个 Claim 至少有一个可回指的 Evidence Unit 和 source SHA。
4. 两位领域专家完成独立审核。
5. 所有分歧有仲裁记录。
6. X 题完成跨来源必要性核验。
7. N 题完成限定范围内的缺失证明。
8. P 题只使用附件来源，W 题冻结抓取/更正时点。
9. 候选题、拒绝项、修订历史和最终锁定文件均有 SHA。
10. 人工 reviewer 和 UTC 时间完整，且没有用 B2 回答回填 Gold。
