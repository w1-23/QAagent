# 意图/路由评测，避免误称“分类器准确率”

8类×24条=192条单意图任务，另24条复合任务，均为候选数据，需双人检查意图与可执行性。含clear/paraphrase/distractor三难度。为避免简单模板泄露，审稿时应报告模板化构造的限制，最好增加真实用户原话独立外部测试集（如经匿名化同意的真实历史意图）。

**标签类别**：GENERAL（普通解释无工具）、LOCAL（仅本地）、WEB（仅联网）、FUSION（两种检索）、PDF_READ（仅读附件）、TABLE_AUDIT（表格审查）、VERIFY_REFS（DOI核验）、EXPORT（成果交付）。对应 `required_tool_groups` 中`local,web,read_file,inspect_table,audit_data,verify_refs,export` 等。

重要：V15没有经核实的显式8类预测变量/分类器；这些是**任务期待的工具执行模式**。主要测`required`完成、`forbidden`违约、无结果透明失败；只有提取到独立的`predicted_intent`才能另报“意图识别准确率”，需要对其类别映射预先登记。真实轨迹中的多个工具调用不能强行映射为单一intent来提高准确率。对于`general`应检查没有检索或额外成果工具。融合请求里的两边检索应有独立成功/无结果记录，不能只看工具被暴露。

候选意图题可能因附件不对应所问领域而**正当答为未找到**：此时评分看工具执行是否符合约束，答案正确性属于另外的QA指标，不应把不相关PDF编造成相关事实。`FUSION`的泛主题在两个来源均有无关结果的可能性；锁题前检查来源可访问和任务设计合理性。只有先证明工具可用才评价“路由失误”；环境失效另列。前8条每类为明确指令，其余为改写与诱导项。

**主图建议**：8类路由满足率与95%CI，以及目标工具组vs实际主工具组的观察矩阵（需显著标明“observed action routing”，而不是预测intent classifier）。复合任务用集合F1/约束违规率，不合并到单标签准确率。
