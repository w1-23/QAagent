### 1.2 B0/B1/B2 与 G01–G15 是什么

`B0/B1/B2` 是三个对照条件，不是三套语料，也不代表三个不同问题集：

| 条件 | 中文名 | 能看到什么 | 不看什么 |
|---|---|---|---|
| `B0` | 纯大模型回答 | 只接收题目和提示词，调用与 B1/B2 相同的基础模型 | 不检索本地语料、不联网、不读附件、不调用科研工具 |
| `B1` | 公平简单 RAG | 与 B2 相同的模型、来源范围、附件正文、检索预算和解析结果；由“检索→拼接上下文→生成”这一条简单管线回答 | 不使用 Agent 的工具编排、表格审查、原文阅读、产物生成和交付链路 |
| `B2` | CitrusScholar 完整实验版 | 最后更新且经过 G01 锁定的完整平台；允许使用题目授权的检索、原文阅读、附件、工具和产物交付 | 不获得 B1 看不到的额外标准答案、目标 chunk 或测试标签 |

`B0` 用来观察“没有证据时会怎样”，`B1` 是公平的同源简单 RAG 对照，`B2` 是完整平台。三者使用同一模型、温度、题面、来源和附件边界；核心差别是检索与工作流能力。

`G01–G15` 是正式运行前的 15 个检查门，不是 15 个实验：

| 门 | 检查内容 |
|---|---|
| G01 | 锁定服务器独立实验实例：Git commit/tree、部署 SHA、`/health`、模型、索引和 17 工具；生产目录只读 |
| G02 | 验证 SSE 当轮正文、`done.answer`、历史正文与下载文件一致 |
| G03 | 验证 HTTPS、账号权限和跨账号数据隔离 |
| G04 | 确认五类语料在当前账号下可访问，并登记来源 generation/SHA |
| G05 | 确认 60 个 core QA 和 60 个 citation 题所需来源、附件或目标定位可读取 |
| G06 | 完成 120 题的两名评审有效性认证，并仲裁分歧 |
| G07 | 确认 B1/B2 使用同模型、同来源范围、同附件文本和可比较的检索预算 |
| G08 | 确认请求、SSE、工具轨迹、失败、回答和产物 SHA 都能完整保存 |
| G09 | 只用独立 pilot 题完成流程试跑，不用正式题调试 |
| G10 | 在服务器独立实验实例中，本地检索、联网、附件、表格审查、引用核验和导出各有一条真实执行证据 |
| G11 | 冻结 Agent 与三判官配置、双专家评分/仲裁材料、缺失/超时规则、终点和统计脚本，并完成校准 |

### 1.3 正式题禁止启动的条件

在以下事项完成前，只允许计划、许可核验、冻结输入审计和实现准备。所有测试、数据库检查、模型探测、适配器验证和 Pilot 均在服务器独立实验实例执行；本地不得运行实验、模型或分析命令。外部 GPT 审查与必要的凭据轮换未完成前，不开始服务器执行：

1. G01–G12、G14、G15 未全部 `PASS`。
2. 统一 120 题有效性还未完成 240 条独立评审/仲裁，或核心 QA60 尚未形成锁定副本，或补充冻结链未通过。
3. `model_config.json` / `judge_config.json` 仍为 `UNCONFIGURED`，或 B1/B2 没有真实、可审计的运行接口。
4. HTTPS、账号隔离、五类语料授权或 P 组附件读取边界未核验。
5. 仍有人试图用“模型检索不到”代替“文献没有该数据”，把自动引用定位命中当成答案正确，或在未完成两名评审有效性认证时启动正式集。
6. `00_protocol/locked_manifest.json` 尚未由人工批准后生成。

4. 验证脚本：验证真实工具状态、SSE、附件、产物、失败记录。
5. 评分/汇总脚本：只读原始记录，不覆盖专家原始输入或仲裁记录。
6. 本实验的配置快照与脚本 manifest。

共享库可以复用，禁止共享运行结果。一个实验不得写另一个实验的原始目录。

## 4. 数据留存总规则

### 4.1 不可变原则

1. 原始运行、SSE、工具轨迹、附件、产物、题目有效性评审、两位专家原始评分、专家仲裁、机器判官原始响应和机器仲裁记录只追加、不覆盖。
2. 每次尝试都生成新的 `attempt_id`，例如 `QA_V09_B2_T1_R2`；失败后重试不能在原文件上改状态。
3. 文件名进入实验目录前先登记 SHA-256；同名不同源文件不得覆盖，必须加 `source_id` 或 `attempt_id`。
4. 正式输入锁定后，任何改动都创建新 protocol version，并写 `00_protocol/change_log.csv`，不能静默替换。
5. 服务器日志若含用户信息，只在受控内部保存原日志及 SHA；发布包只放脱敏摘录。不得以脱敏为由删除原始失败记录。
6. 所有修正通过新文件完成；判官或评分错误用 `correction_of` 指向被纠正记录，并保留原值。
7. 以 UTC 记录时间，同时保留本地时区说明。不得用文件修改时间代替实验时间。

### 4.2 每个运行的完整记录

`06_runs/raw/<condition>/<run_id>.json` 至少包含：

| 字段组 | 必填内容 |
|---|---|
| 身份 | `run_id`、`attempt_id`、`experiment_id`、`case_id`、condition、trial |
| 协议 | `protocol_version`、`locked_manifest_sha256`、`run_plan_sha256`、`script_sha256` |
| 环境 | OS、CPU、内存、GPU/provider、客户端版本、服务实例 URL/匿名 ID |
| 版本 | Git SHA、部署 SHA、模型精确 ID、提示词 snapshot SHA、索引 generation、BM25/embedding/reranker 版本 |
| 参数 | temperature、top_p、seed、max tokens、timeout、top-k、context budget、缓存策略 |
| 输入 | 完整 prompt、来源范围、附件原文件名、附件复制件、附件 SHA、网络检索时间窗 |
| 输出 | raw answer、final answer、citations、sanitized raw events、工具调用与状态、产物路径与 SHA |
| 计量 | 开始/结束 UTC、wall time、first token、tokens、费用（可缺，不得伪造） |
| 终态 | `completed/partial/failed/no_results/cancelled/skipped`、错误、是否环境不可用、是否重试 |
| 核验 | 下载是否成功、下载 SHA、当轮正文、`done.answer`、历史回读正文是否一致 |

每个运行另存：

```text
06_runs/raw/<condition>/<run_id>.json
06_runs/events/<run_id>.jsonl
06_runs/tool_traces/<run_id>.json
06_runs/logs/<run_id>.client.log
06_runs/logs/<run_id>.server_excerpt.log
06_runs/screenshots/<run_id>/
06_runs/artifacts/<run_id>/
06_runs/download_checks/<run_id>.json
06_runs/failures/<run_id>.json
```

目录内不存在的文件必须由该运行的 manifest 显式标为 `NOT_APPLICABLE`、`NOT_PRODUCED` 或 `CAPTURE_FAILED`，不能通过省略字段掩盖。

### 4.3 全流程留存链

| 阶段 | 必须留下的数据 | 结束证据 |
|---|---|---|
| 协议 | 计划、变更、审批、哈希 | `locked_manifest.json` |

### 4.4 备份与恢复

1. 在每个阶段完成、正式锁定前、正式分析和投稿前做只读备份。
2. 备份必须包含原始文件、SHA 清单和恢复记录；不得只有“分析后结果”。
3. 每次从备份恢复后重跑 `check_package.py`、schema 校验和关键 SHA 校验。
4. 不删除失败运行、超时、取消、评分分歧和修订历史。
5. 若必须因安全原因隔离敏感材料，保留哈希和事件记录，将文件移入受控隔离区，不把违规内容放入公开 release。

### 4.5 数据留存与公开边界

| 等级 | 内容 | 留存与发布 |
|---|---|---|
| `L0` | API Key、Cookie、密码、token、认证头、私有身份链接 | 永不进入实验包、Git、日志、截图或对话 |
| `L1` | 未获再分发许可的全文/受限摘录、私有 SOP、身份映射、原始敏感日志 | 完整保留在服务器受控存储；GitHub 只放 SHA、定位、访问等级、redaction log 和公开衍生物 |
| `L2` | 可公开题面、许可允许的证据定位/摘录、脱敏运行、SHA、盲化评分、统计、图和论文材料 | 通过 release 检查后才允许进入 GitHub |

“保留全部原始数据”不等于“公开全部原始数据”。公开检查至少覆盖账号、用户标识、
附件内容、签名 URL、Authorization 头、个人信息、盲映射和材料再分发权。许可证
不明或 `L1` 内容不得上传；原始证据不得为满足公开要求而删除。

4. 核心 QA60 是原计划的正式实验，不因新增 citation60 而废弃；其 180 个运行不得与补充实验合并。

**补充实验研究问题**：在相同底层模型、相同允许语料和同等检索预算下，完整平台 B2 相比公平 simple RAG B1，是否更常给出能定位到预先冻结原文 chunk 的引用；B0 仅作无本地检索诊断。该实验补充核心 QA60 的可核验定位证据，不替代核心问答质量评价。  
**设计**：60 题×B0/B1/B2×1 次，共 180 次；每题每个条件独立新会话，禁止跨题记忆。  
**分析单元**：一个 `question_id` 恰好对应一个冻结 `target_chunk_id`；60 个 chunk 是 60 个不同的主要来源簇。  
**随机化**：运行计划使用 seed `20261104` 打乱 180 个 run；评分包隐藏 condition 和 adapter。条件顺序不能在同一题内形成固定提示偏差。  
**输入**：

1. `03_benchmarks/citation60/chunks_FROZEN.jsonl`：60 个冻结 chunk 及来源元数据；完整正文属于 `L1`，只从服务器受控目录读取。公开树不含该文件。
2. `03_benchmarks/citation60/questions_FROZEN.jsonl`：60 道冻结问题及 target 指针；运行器不得读取 target 字段。
3. `06_runs/manifests/citation_run_plan.csv`：唯一运行时计划；只含题干、允许语料名、condition 和工具约束。
4. 来源许可、索引 generation、B0/B1/B2 模型与检索配置；G01/G05/G07 通过后才允许正式运行。

**抽样与冻结**：

1. 从 active index `g20261028T165637Z_851926a9` 的五类语料来源各随机抽 12 个 chunk，seed `20261104`，正文长度 300–3500 字符。五类来源不是“五类公开柑橘语料”，其中 methods/literature/translated 可能包含非柑橘材料。
2. 抽样先按不可变 chunk ID 排序，再使用 `random.Random("<seed>:<corpus>")` 抽样；相同 registry/seed/参数必须得到相同 chunk ID 集。
3. 每个 chunk 冻结 `chunk_id`、`paper_id`、`source_file`、`title`、`section_name`、`registry_id`、索引 generation、registry/chunk 文件 SHA 和正文 SHA。
4. 冻结后不得覆盖。抽样参数、语料 generation、chunk 正文或 seed 任一变化均新建版本目录和新 SHA。

**逆向出题与冻结**：

1. 出题者或 agent 只从服务器受控 `L1` 目录读取 `question_authoring_packet.jsonl` 中对应的一个 chunk，先写一句可审计的关键事实锚点，再逆向生成一个自然中文问题。该包含完整正文，禁止进入公开树。
2. 问题必须只依赖该 chunk 可答；不得使用其他语料、联网结果或任何 B0/B1/B2 回答。
3. 自动预检：60 个 `citation_id` 恰好各一题、题干唯一、`answerable_from_chunk=YES`、目标 chunk 哈希一致、题干不含 chunk ID/源文件名、题干不与原文共享 8-token 连续片段。
4. 运行计划禁止出现 `target_chunk_id`、`target_paper_id`、`target_source_file`、`chunk_text`、`anchor_for_audit` 等字段；`50_verify_freeze.py` 必须返回 `PASS`。
5. 两名领域评审（可为研究生）逐题独立确认“问题可答、无歧义、来源可达、范围正确、无定位符泄漏”；不一致时仲裁。全部 120 道实验题使用同一有效性规程。

**条件**：

1. B0：同底层模型直接回答；不提供本地检索、联网、附件全文或平台工具。B0 的主要作用是显示无外部证据时引用缺失，不作为架构优势的公平对照。
2. B1：同一模型、同一五类语料快照、同一分块/embedding/top-k/reranker/context 预算；单脚本 retriever +统一回答/引用 prompt；不提供 CitrusScholar 集成工具。B1 必须真实返回可审计的 citations，不能只用关键词或伪造来源。
3. B2：真实 CitrusScholar UI/API、真实账号权限和工具轨迹；只允许命中题目声明的语料，原样保存 SSE、工具调用、最终正文、citations 和历史回读。
4. 三个条件都不接收 `questions_FROZEN.jsonl` 的 target 字段；B1/B2 的来源范围严格等于 `source_scope`。附件/联网工具在 E01 中禁用。

**自动引用判定**：

1. `target_chunk_cited=1`：运行结果的 `citations`/`sources` 中明确出现冻结 `chunk_id`。这是本补充实验内的唯一主自动终点。
2. `target_document_cited=1`：明确出现 target `paper_id` 或 `source_file`；chunk 命中自动计为文档命中。
3. `allowed_corpus_cited=1`：引用含目标语料 ID/路径，或已经命中 target chunk/document。
4. `wrong_corpus_cited=1`：引用出现其他四类语料的明确标识；不能靠标题猜测。
5. `no_citation=1`：`citations`/`sources` 为空且最终正文没有 `[n]`、URL、DOI 或“来源：”等可核验信号。
6. 检索工具日志命中但最终 `citations` 未引用，不算 `target_chunk_cited`；另存于工具轨迹供诊断，不得把“检索到”冒充“引用到”。

**明确不报告的指标**：

1. 不报告 semantic support、原文语义支持率或 `1/0.5/0` 人工支持等级。
2. 目标 chunk 自动命中只表示最终引用包含该 chunk 标识，不表示答案正确或被原文支持。
3. 参考文献或标题出现在答案中但没有最终可核验引用时，仍记 target chunk 命中为 0。
4. 回答引用合法替代来源只作描述性诊断，不能改变预注册终点，也不能升级为 semantic support。

**统计**：

1. 补充实验总体终点：60 题 `target_chunk_cited` 的 micro-average；五个语料各自报告命中率与 Wilson 95% CI。
2. 主对比：B2−B1 的逐题配对差；按语料分层，使用题内配对、分层
   bootstrap 95% CI，seed `20261104`，10,000 次。
3. McNemar exact 双侧 p 值仅作预注册描述性检验；同时报告效应量和完整 2×2 转移表，不以单一 p 值作结论。
4. 次级终点：target document cite、allowed corpus cite、no citation、wrong corpus cite。
5. B2−B0 仅作描述性诊断；B0 无检索时不应预期命中本地 target chunk。
6. 60 个来源簇各不相同，不把同一 chunk 的 B0/B1/B2 当独立来源；分层 bootstrap 和成对分析必须保留配对关系。
7. 缺失 raw run 不从计划分母消失。按 `09_analysis/FAILURE_DENOMINATOR_MATRIX.md` 分开记录 `completed/partial/failed/no_results/cancelled/skipped`、空回答、正确拒答、工具失败、服务不可用、传输失败和 `RAW_RUN_MISSING`；缺失记录不能被伪造成成功或失败观察，并使 strict gate 失败。

**输出与留存**：

1. 原始运行：`06_runs/raw/B0|B1|B2/CC60_*_T1.json`、events、tool traces、failure ledger；每次尝试独立 `attempt_id`，不覆盖。
2. 自动观察：`07_scoring/reviews/citation_hit_observations.csv`；不得把检索日志当最终引用。
3. 不生成人工语义审计表。
4. 分析表：`09_analysis/tables/citation_hit_rates.csv`、`citation_paired_effects.csv`。
5. 图/表：Supplemental Fig.S3、Supplemental Fig.S4、Table S1–Table S2；图必须从真实分析表生成并登记 SHA。
6. 冻结与脚本：公开说明 `03_benchmarks/citation60/README.md`、受控资产清单 `12_reproducibility/L1_CONTROLLED_ASSET_MANIFEST.json`、受控 `chunks_FROZEN.jsonl`/`question_authoring_packet.jsonl` 及其余 14 个 G12 待审资产、`scripts/E01_chunk_citation/` 和对应测试；正文与未审 metadata 只在受控存储，运行记录、判官响应和评分按 L1/L2 逐文件发布审查。

**共同失败规则**：环境/模型不可用、B1/B2 适配器未真实接通、答案无法保存、引用无法解析或来源 SHA 不一致时停止该运行并保留真实终态；不得把缺失 raw run 补造为观察。可评估的空回答/拒答进入语义评分，基础设施失败作为系统任务失败进入意向分母并单列，缺失记录使 strict gate 失败。锁定后不得更换目标 chunk、删题、改题干或把自动命中改成人工命中。

**关系边界**：`E01_QA60_EGTS` 与 `E01_SUPP_CHUNK_CITATION60` 都是正式实验。前者以专家共识评价答案质量、拒答和证据使用，LLM 判官作为独立自动测量；后者由确定性规则评价目标 chunk 引用定位。两者分别报告，不合并分母或互相替代。

### 7.3 E02 单意图/动作路由 192

**研究问题**：用户在 8 类任务目标下的真实工具执行是否符合允许动作，以及是否越界调用禁止工具。  
**样本**：8 类×24，共 192；clear/paraphrase/distractor 三类难度。  
**设计**：仅 B2，每题独立新会话；工具可用性在测试前逐条检查。  
**期望动作集**：不是模型潜在内部标签，而是用户期望执行的功能组、必需工具组、禁止工具组和来源范围。

**指标**：

1. `available_n`、`unavailable_n`。
2. 条件于工具可用的 required-met 且 forbidden-not-violated 比例。
3. 每类 Wilson 95% CI。
4. `target family × observed primary group` 矩阵；明确标注为执行代理，不是分类器预测。
5. 禁止动作违规率、零结果透明失败、环境不可用率。

**判定**：GENERAL 无必要工具；不得无端检索或导出。附件/网络不可用时，先记 `environment_unavailable`，不得进入路由正确率分母，但必须在可用性失败中报告。

## 8. 评分与仲裁操作

### 8.1 E01 核心 QA60 与补充 Citation60

1. 核心 QA60 的每份回答由两位领域专家独立评分；任一四维字段
   `answerability_correct`、`answer_correct`、`evidence_traceable`、
   `fatal_error` 不一致时由第三位专家只仲裁争议字段。人类共识为 QA60 主测量，
   LLM 判官评分为独立自动测量。专家不填写最终 EGTS。
2. Judge 1、Judge 2 分别对全部 180 份 QA60 回答独立评分；四维字段任一不一致时调用
   Judge 3。理由码或文字不同不触发仲裁。模型输出不得包含自行生成的
   `decision`/PASS/FAIL；原始请求/响应、每个 attempt 和评分只追加、不覆盖。
3. 补充 citation60 从 180 个真实 run 提取 `citations`/`sources`，计算 target chunk、target document、allowed corpus、wrong corpus 和 no-citation；检索日志只作诊断。
4. 补充实验的自动定位必须覆盖 180/180；缺失、失败和无法解析状态单列，不能从分母静默消失。
5. 不生成 semantic-support 包、不调用人工语义评审、不报告语义支持率。
6. 自动 target chunk 命中不得写成“引用正确/原文支持/答案正确”。
7. 人类共识和机器判官聚合分别计算、分别留存；不得以 LLM 结果覆盖专家评分或用单一判官决定主结果。
8. 三个判官的模型 ID、实际响应模型、版本/指纹、prompt、packet、request/response
   SHA、usage、cost/list_cost/allowance、错误、耗时和重试全部进入锁定与分析
   manifest；专家原始表、attestation 和仲裁亦记录 SHA。
9. `strict-human`、`strict-judge`、`strict-citation` 和 `strict-all` 分开计算。
   机器判官缺失不得阻止完整的人类主结果分析，但必须使 `strict-all` 失败并明确披露。

### 8.2 路由与复合

1. 先由确定性规则从工具轨迹读取 `available`、required、forbidden、observed group；规则无法归类时才调用冻结 LLM 判官。
2. 对模糊工具别名使用预定义工具组映射；不把工具失败当模型动作错误。
3. 环境不可用单列；无结果透明失败单列。
4. 复合 24 的目标与 observed 集合用 `|` 分隔；禁止把集合强行映射成单一类别。
5. 评分者看工具真实事件而非仅 final answer 自述。

### 8.3 工作流

1. `1`=通过，`0`=失败，`NA`=有明确理由不适用；无法验证证据记 0。
2. 每个 criterion 先由脚本填写真实 `evidence_path`、SHA 和 UTC；只有定性验收需要冻结 LLM 判官。
3. 关键项失败使工作流不能算完全完成。
4. 只写“文件已生成”而没有文件/SHA 记失败。
5. 记录所有步骤的人工介入与时间点。
