## 1. 目标与边界

本计划把实验数据、统计结果和论文写作连成可审计链路。目标论文定位为
CitrusScholar 系统、实验方法和真实可复现结果，而不是预先宣称 B2 更优、
宣称模型具有通用科学智能，或用模拟数据填充 Results。

写作必须满足：

1. 每个数字可追溯到锁定的 raw run、专家评分/仲裁、判官响应、确定性评分或分析脚本。
2. 核心 QA60 与补充 citation60 分开报告，不共享分母，不互相替代。
3. 不报告 semantic-support 或语义支持率。
4. 人类专家共识是 QA60 语义测量；机器判官是独立自动测量，披露模型、版本、prompt、
   成本、J3 仲裁和与人类共识的一致性。专家收到六批各 30 个正式盲包，同一题的
   B0/B1/B2 分散到不同批次；Pilot 为三批各 12 个。
5. 模拟数据只用于工具链测试，论文中最多出现在软件测试/可复现性说明，
   不得出现在正式结果。
6. 失败、取消、超时、缺失和环境不可用必须进入结果或补充材料，按
   `09_analysis/FAILURE_DENOMINATOR_MATRIX.md` 区分
   `completed/partial/no_results/failed/cancelled/skipped` 和
   `RAW_RUN_MISSING`；不得用成功子集替换计划分母，也不得伪造缺失观察。
7. 所有证据都保留，但公开按 `L0/L1/L2` release 规则处理；论文不得把未获再分发
   许可的源文或受限日志作为公开补充材料。

## 4. 写作顺序

### W00 仓库审计

1. 在服务器独立实验实例运行 `scripts/check_package.py`、冻结校验、模拟校验和测试；本地只编辑、审查和提交文档/代码，不运行实验或分析命令。
2. 确认 `G01-G15` 当前状态，不得把 `BLOCKED` 或 `PENDING` 写成已完成。
3. 确认模拟输出带 `SIMULATED_DRY_RUN`。
4. 产出：审计问题清单，不修改结果。

### W01 方法与系统事实

1. 从实际源码确认单 General Agent、17 工具、权限、检索和产物路径。
2. 写数据来源、五类语料来源及其领域/许可边界、B0/B1/B2、题目有效性、
   双专家评分/三专家仲裁、LLM judge 和统计。B1/B2 报告每题模型调用、输入/输出
   token、成本、耗时、检索、context 和工具调用硬预算及实耗。
3. 写清核心 QA60 与 citation60 是两个独立正式实验。
4. 所有方法段落进入 claim-source map，状态先记 `SUPPORTED_BY_PROTOCOL`。

### W02 结果表生成

1. 正式运行和评分完成后，执行严格分析。
2. 生成 `09_analysis/tables/`、`analysis_manifest.json` 和图数据；记录 percentile
   bootstrap、NumPy `PCG64(20261104)`、alpha、AC1/kappa 和 52 题 NA 适用性。
3. 每个表格由脚本直接填充，不手工输入。
4. 失败与缺失单独成表，不从计划分母删除；`RAW_RUN_MISSING` 直接阻断 strict。
5. `strict-human`、`strict-judge`、`strict-citation` 与 `strict-all` 分开记录；
   机器判官缺失不阻止完整人类主结果，但阻止 `strict-all`。

### W03 Results

按以下顺序写：

1. 核心 QA60：以 `egts_system_outcome` 报告确认性系统任务结果，并单独报告
   `human_consensus_egts`、语义评分覆盖率、answerability、answer correctness、
   evidence traceability、fatal error、分层结果和基础设施失败；机器判官及其与
   人类一致性单独报告。
2. 补充 citation60：五类语料来源分别报告 target chunk 命中、文档/语料/错误语料/
   无引用。`cqa_methods`、`cqa_literature`、`cqa_translated` 可能非柑橘材料；
   不称五类公共柑橘语料，不推断柑橘文献总体，不报告 semantic support。
3. 路由 192：可观察执行合规，不称 classifier accuracy。
4. 复合任务 24：工具集合、必需与禁止动作。
5. WF01-WF07：交付物、SHA、失败边界和 WF07 融合案例。
6. 负结果、取消、超时和环境不可用。

每个小节只引用已存在的真实表。没有表时写 `PENDING`，不得写预测值。

### W04 Discussion 与 Conclusion

1. Discussion 不重复 Results 数字。
2. 解释同源 B1/B2 差异、失败模式、人工在环和适用边界。
3. Conclusion 只包含真实实验支持的结论。
4. 不使用“通用智能”“自动科学发现”“全面优于”等无证据措辞。

### W05 图表定稿

1. 每张图必须有 `table_figure_provenance_TEMPLATE.csv` 对应行。
2. 图只能从对应的 `strict-human`、`strict-judge`、`strict-citation` 或
   完整 `strict-all` 数据生成；未通过的模块不得出图。
3. 多面板图统一字体、字号、尺寸、颜色与误差说明。
4. 图题不写超过统计支持的因果结论。

### W06 摘要与投稿

1. Abstract 最后写，数字逐项与 Results 对齐。
2. Availability 声明列出代码 commit、可公开冻结题面、来源定位、脱敏运行、评分、
   判官响应、分析脚本和图数据；明确哪些原始证据因许可或隐私属于 `L1`，只公开
   SHA、定位、访问等级和 redaction lineage。
3. 单独列出未运行的实验、失败和协议偏离。
4. 执行 release checklist、secret scan、link check 和数字一致性检查。

## 7. Claim-source 纪律

每个事实性主张必须登记：

- `claim_id`
- 所在章节
- 主张文本
- 主张类型：实现事实、实验结果、案例观察、设计解释、未来假设
- 原始来源/表格/图
- 定位字段
- 分析脚本 SHA
- 验证状态与验证人

没有登记来源的主张不得进入正文。合作者待办和无法证实事实只能作为内部任务，
不能写成论文结论。

## 8. 表格、图件和文本一致性

提交前执行：

1. Abstract、Results、Discussion、Conclusion 的同一数字完全相同。
2. 表格数字与图数据一致。
3. 图题中的 `n`、条件、误差和检验与表一致。
4. 正文引用的表图编号存在。
5. `B0/B1/B2`、`E01_QA60_EGTS`、`E01_SUPP_CHUNK_CITATION60` 术语固定。
6. `semantic_support` 作为已报告指标的出现次数为 0；正文只允许明确说明不报告该指标。
7. `evidence_traceable` 与旧字段命名不得混用。
8. `SIMULATED_DRY_RUN` 不进入 Results。
9. `B2 vs B1` 是唯一主要确认性比较；`B1/B2 vs B0` 只能描述性报告。
