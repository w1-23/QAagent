# CitrusQA 连续人工测试包

这些测试按真实使用情境编写。**请把“对话”中的句子直接发给 CitrusQA，不要在聊天里说“调用某工具”或照抄测试者观察。**这样才能检查主 Agent 是否理解问题并选对路径。

## 开始方式

1. 每个编号目录新建一个会话；同一目录里的问题按顺序连续提问。
2. 只在题目注明时上传指定附件。附件可以重复上传，确保当前问题明确带有所需文件。
3. “测试者核对说明/观察”仅供测试者判断结果，不要复制给模型，也不要写进附件。
4. 每组结束后保存页面中的回答、工具轨迹和下载产物，再进入下一组。

## 场景顺序

1. `01_基础问答与连续会话`：真实课题咨询；单纯上传附件不应自动审查。
2. `02_本地与联网检索`：围绕柑橘无融合生殖连续查证公开文献和本地语料。
3. `03_论文解析与参考文献`：准备组会，解读合成短稿并核验真实/负例 DOI。
4. `04_统一数据审查`：从合作组仪器表字段不清开始，逐步审查质量、复杂关系和正常对照。
5. `05_可视化与科研导出`：为耐盐预实验准备流程图、方案文件，并检查图片理解。
6. `06_异常边界`：模拟空白田间记录和损坏工作簿，检查失败状态表达。

## 使用附件的约定

- 数据、论文和图片均是测试材料；出现的异常是人工合成的，不代表真实科研错误。
- 除“测试者核对说明”外，异常提示不写入数据附件，避免模型从文件名或单元格直接抄答案。
- 表格审查应提供已读取文件/工作表范围、跳过项和未完成项；异常只作为待人工复核线索，不能据此判定错误或不端。
- 数据审查应只生成一份自动命名的 HTML 异常报告；其他科研导出按工具类型提供对应文件。打开报告核对内容，原始附件应保持不变。
- 联网未完成、额度不足、权限错误、零搜索结果和本地零召回应分开说明。
- 本包供人工真实模型验证，不提供测试答案给模型，也不替代对模型路由、联网和网页显示的实际检查。
