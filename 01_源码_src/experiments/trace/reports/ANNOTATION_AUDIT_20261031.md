## 1. 为什么改

旧实现是「八项规则扫描 + HTML 异常报告」：`_audit_frame()` 跑缺失值/常量列/混合数值/IQR 离群/重复行等检查，
再由 `_render_audit_html()` 渲染成一份汇总报告。

问题：
- 报告按**检查类别**汇总，用户要按**行**看结论，得自己在报告和原表之间来回对；
- 规则命中只是线索，报告里没有「这一行为什么值得看」的自然语言理由；
- 用户明确要求改成「AI 审查数据，然后逐行标注理由」。

## 2. 现在怎么工作

1. 模型先 `inspect_uploaded_table` 看字段与行号；
2. 模型逐行判断，调用 `audit_uploaded_data` 时传入 `annotations_json`：
   ```json
   [{"row": 4, "level": "review", "reason": "141.5 是同组另两株的 3.4 倍，疑为录入多打一个 1"}]
   ```
   - `row`：**原文件行号**（含表头偏移，首个数据行通常是第 2 行）；
   - `level`：`ok` / `review` / `error`（也接受「正常 / 需核对 / 错误 / 可疑」等表述，内部收敛到三档）；
   - `reason`：一句话依据；`field` 可选，指出涉及哪一列。
3. 工具生成 `<原名>_标注.xlsx`：原始行列原样保留，右侧追加三列
   「审查结论 / 审查理由 / 涉及字段」，并按级别着色（正常绿、需核对黄、错误红）；
4. 另生成「标注说明」工作表：原文件、工作表、数据行数、标注行数、未标注行数、生成时间、说明与提醒；
5. **原文件只读**：`_load_frame()` 读内存副本，导出走 `_save_artifact()`；未标注的行留空，不默认写「正常」。

## 3. 关键实现

| 位置 | 作用 |
| --- | --- |
| `_normalize_annotations()` | 校验 row/level/reason，非法输入直接报错而不是静默丢弃 |
| `_annotation_level()` | 把模型措辞收敛到 `ok/review/error`，保证不同表述进表后口径一致 |
| `_annotation_style()` | 三档配色 |
| `_write_annotated_xlsx()` | 组表：原始列 + 三列标注 + 说明页；越界行号记入 `warnings` |
| `audit_uploaded_data()` | 工具入口：多文件/多工作表循环，逐表产出，返回 JSON 摘要 |
| `src/tools/__init__.py` | `produces` 由 `audit_report` 改为 `annotation_table` |
| `src/api/main.py` | 附件提示改为「先 inspect 再按行标注」，不再提「统一审查报告」 |

## 5. 已知边界

- 标注质量取决于模型判断；工具只保证「行号对齐、口径一致、原件不改」。
- 一次调用只处理你给出的标注；未标注行保持空白（后续可再调一次补齐）。
- 单表行数很大时不建议一次全标（模型上下文有限）：当前建议分批标注，工具本身不限行数。
- 「是否修改原件」不可配置：始终只读。
