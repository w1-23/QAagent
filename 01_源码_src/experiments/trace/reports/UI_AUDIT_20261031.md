## 2. 问题清单（按严重度）

### P1-1 等待文案在三套主题中的浅色两套对比度不足

- 实测（逐层 alpha 合成后的真实背景，14.5px / weight 500）：

| 主题 | 前景 | 背景 | 对比度 | WCAG AA（4.5:1） |
| --- | --- | --- | --- | --- |
| light 春日花笺 | `#C9761F` | `#FAFCF9` | **3.33** | 不达标 |
| cartoon 夜林花语 | `#B9722A` | `#FAF4EA` | **3.49** | 不达标 |
| dark 午后书房 | `#E8AE5A` | `#181818` | 9.01 | 达标 |

- 影响：等待文案是“随时可读”的状态提示，弱视力用户与外光环境下偏难辨认。
- 建议：只改 `--loading-accent` 的两个浅色值，保持橙色主张：
  - light → `#A5560F`（实测 **5.17**）
  - cartoon → `#9E5A16`（实测 **4.89**）
  - dark 保持 `#E8AE5A`（8.99）
- 备选：保持取色、把文案改为 15px/600 并加深 1 级；仍达不到 4.5 则只能改色。
- 预估：改 2 行 CSS + 复测 10 分钟。

### P2-1 弹层的 ARIA 语义不完整

- 现状：容器 `role="menu"`、`aria-label="宠物设置"`，但子项没有 `role="menuitem"`，也没有方向键导航；打开后焦点仍停在触发按钮上（面板内 5 个可 Tab 控件）。
- 影响：屏幕阅读器会先播报“菜单”，再用 Tab 越过子项时语义断裂。
- 建议：要么补 `role="menuitem"` + ↑↓ 循环 + `tabindex="-1"` 漫游焦点；要么把容器降级为普通 `div`（`aria-label` 保留），改叫“弹层”而不是“菜单”。后者更省事，行为与现状一致。

### P2-2 空会话时抽屉文案自相矛盾

- 现状（430px 实测截图）：`会话历史 0 条消息 · 0 字符` 与 `0 / 1,000,000 · 刷新后的会话文本估算` 同时出现；额度条满格、百分比 `0%`。
- 影响：用户会以为“有 100 万额度却只有 0 字符”是坏了。
- 建议：会话为空时不渲染额度条，改为一句 `当前会话还没有消息`。

### P2-3 遗留 id 分支

- `web/assets/mascot.js:336` 仍 `getElementById('mascotToggleBtn')`（该按钮已在 Round 13 拆层时移除），靠 `if (btn)` 兜底，无实际作用。
- 建议：删掉该分支与注释里的旧名，避免下次误判“文案唯一写入点”。

### P2-4 窄屏缺“实际发送给模型”表

- 430px 下 `.ctx-sent-table` 不存在（抽屉其余部分正常）。需确认是媒体查询隐藏还是渲染分支跳过。
- 建议：若是有意隐藏，在抽屉里给一句 `窄屏下不展示请求快照`；若是缺陷，补横向滚动容器。

### P3-1/P3-2 工程卫生

## 3. 方法学更正（留痕）

第一版对比度测量直接用 `getComputedStyle().backgroundColor` 的 RGB 分量计算，忽略了这些背景是**半透明**的（如 `rgba(255,255,255,0.06)`），
得出 dark 主题 `1.97:1` 的结论——**这是假阳性**。改为逐层 alpha 合成后，dark 实测为 `9.01:1`（达标）。
报告内所有对比度数值均以 `probe_contrast_composited.js` 为准；`probe_focus_contrast.js` 的旧数值仅作参考，不得引用。
