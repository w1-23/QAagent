# CitrusScholar 科研工作区完整实施方案

更新：2026-11-14。此方案合并此前批准的工作区改造，以及用户追加的 Nature skill 内部适配、技能扩展接口、能力与场景分离、按需生成文件要求。实施已在隔离分支 `feat/research-workspace` 进行；本文是目标和验收范围，不是全部已通过的声明。

## 1. 产品与架构边界

服务器提供预装科研环境的隔离工作空间，Web 提供自然语言交互、必要选择、成果预览和资料库。LLM 可以自主读数据、编写代码、运行、观察日志、局部修改并继续执行。任务材料跨轮保存；执行进程按次启动和退出。

**工具能力、预设场景、技能和交付形式分别定义：**

- 能力：检索、读取、核验、数据检查、计算、代码读写与执行、成果发布。按权限和环境提供，避免为每个业务名称添加一个工具。
- 场景：科研问答、文献综述、附件解读、实验设计、数据审查、统计和绘图。场景是上述能力的可组合用法，不强制固定路线。
- 技能：方法规范、任务组织、可复用脚本或辅助库。技能通过统一目录发现、按需读取；不能自行提升权限、联网、安装依赖或运行宿主命令。
- 交付：默认有来源、可复制的回答。只有用户要求生成文件、下载、导出或指定文件格式时才发布文件；绘图请求本身需要真实图件。中间表与脚本默认内部保存。

现有预设能力不能丢。现有方法库、格式生成器和系统脚本长期维护；保留能力不等于保留所有旧工具名。复用顺序为：适用工具 → 已有脚本绑定参数 → 派生版本局部修改 → 确有缺口再写新脚本。绘图也遵循此顺序，LLM 不必反复重写已有算法。

## 2. 通用技能接口与 Nature 绘图核心

建立服务维护的只读技能目录，记录名称、版本、来源、许可证、固定提交、文件摘要、入口、依赖、执行适配器、默认/按需材料。统一提供列出技能、读取入口、分页读取参考资源的接口，复用 `research_workspace`，不为每个 skill 注册一个大工具。

默认绘图技能使用用户指定的 [Yuan1z0825/nature-skills](https://github.com/Yuan1z0825/nature-skills/tree/main/skills/nature-figure)，固定提交 `7bff1d0539c0dfad6c30178bb93ce6dd8a5cebf8`、版本 2.8.0。保留 Apache-2.0 许可证、归属、来源和修改说明；原文与本地适配分离。升级通过代码审查和验证，不在生产任务中自动从 main 拉取。

集成重点是绘图核心和美学：

- 研究问题、变量语义、图型选择、证据关系与多面板组织。
- 字体、配色、线宽、标记、图例、留白、面板比例、最终物理尺寸。
- 可复用 Python 绘图和布局辅助函数。
- 源码检查、最终面板对齐、PDF 文字与碰撞检查，检查实际执行并保存回执。
- 图件按需修订后重新检查；检查失败保留代码和诊断，不伪称通过。

不仅注入提示词：将适用的辅助代码和审计实现打包进沙箱，通过平台适配器接入现有脚本执行、QA 和发布。LLM 仍自行编写或修改脚本，技能不替代模型决策，也不把所有图固定为少量模板。

本轮不接入 R、外部图像生成 API、独立安装器或其他外围工作流。期刊特定规范按需读取，不把全部投稿要求强加给普通探索图。技能加载、环境安装、实际检查通过分别记录，缺依赖或不适用不能算通过。

## 3. 脚本资产与跨轮工作区

系统预设能力长期只读；任务脚本默认闲置 7 天后可回收，管理员可配置。保存、执行和真实使用刷新活动时间，列表浏览不无限续期。原始上传只读，中间结果通过授权引用保存。

工作区支持列出、分页读源码、保存、按预期版本局部替换、读取运行记录。内置脚本需要适配时派生任务版本，不覆盖系统文件；相同源码去重，换参数或数据不要求复制代码。

执行前保存精确源码版本，记录 script_ref、run_id、输入快照与哈希、参数、输出契约、环境与技能版本、状态和有界日志。失败、超时、取消同样可追溯。重新执行产生新运行；真正的幂等重放明确标记。

上下文压缩、刷新和后续轮次保留引用，正文按需读取。任务失败采用有限修复预算；换文件名不能绕过，独立任务不被无关失败误伤。正在执行、待答任务或正式成果依赖的版本受到引用保护；账号删除仍清理其全部私有资产。

复用已有 Docker/WSL Docker/Linux 沙箱、v2 `emit.table/emit.figure/emit.report` 协议和图件重放。纯整理可零图；一份数据可多图或多子图；不新建第二套绘图引擎、资料库或问答协议。

## 4. 研究意图与必要澄清

LLM 在读取真实表结构后保留简要工作意图：研究问题、数据来源、变量角色和单位、实验单位/分组/配对、整理选择、图件安排、已确认事实和必要阻塞问题。它是可更新状态，不是强制用户填写表单。

目标和数据明确就直接执行。变量含义、实验单位、配对关系或单位冲突会改变解释时，复用现有 `request_user_input` 给出少量真实字段选项、自定义和取消；答复后继续已有脚本、数据与预算。颜色、普通布局和文件名采用合理默认。

不为画面效果擅自删除异常值、补值或推断实验设计。变换保留行数、列映射、父数据与排除信息。多指标按研究目的选择多图/分面，不把不同量纲强塞到同一轴。统计与图注使用全精度结果引用。

## 5. 能力保留、方法复用与按需交付

检索与候选获取保留；本地候选池与 Web search/fetch 的真实差异如实描述。文献核验保留 DOI/登记信息与来源时间，区分服务不可达、未查到和元数据冲突。

数据审查将原算法提取为共享纯方法，现有工具与脚本复用同一实现。选择性检查必须记录实际覆盖，不能把全扫描后的结果过滤说成只执行所选规则。统计保留前提、效应量、多重比较和不可变数据/结果引用。

审查、核验和统计解耦“执行能力”与“发布附件”：默认返回真实结果、适用性与覆盖；用户要求标注工作簿/核验表/统计文件时再发布。Word 创建编辑、课题笔记保存/回忆等实质操作保留，尊重其授权规则。

六个重复导出入口收敛为统一成果交付适配，底层原生成器继续使用：

| 原入口 | 统一入口内的能力 |
|---|---|
| export_paper_analysis / export_experiment_design | 报告内容 → HTML 等实际支持格式 |
| export_research_notes | 已有课题记录 → 文档 |
| export_table | 结构化表格/分析引用 → CSV、TSV、XLSX |
| export_literature_evidence | 书目/证据结构 → XLSX、RIS、BibTeX |
| export_corpus_gap_report | 已观察缺口 → CSV |

这些是格式能力，不再作为独立预设场景要求用户执行。普通回答不调用发布工具。

需要文件时沿用统一校验、不可变版本、哈希、发布协调和资料库登记。聊天成果卡与资料库共用预览/导出入口。已有格式下载只读取固定版本，不调用模型、不重跑研究；只显示真实已生成或明确支持的格式。标注工作簿保留批注、多工作表与样式，不随意转换为 CSV。旧链接和历史 producer 记录保持可用。

## 6. 完成判断与执行边界

完成依据是用户实际要求、真实运行/检查回执、输入与结果可追溯性、必要澄清状态；只有要求文件时才检查文件合同。报告、方案、综述、证据等名词不自动推导 DOCX/XLSX 附件。

新旧判定对照后迁移，不直接放宽为模型自报完成。统一发布工具可能支持多种格式，但一个普通 XLSX 不能因此被认作文献证据或审查结果。保留显式用户操作、来源限制、所有权、资源预算与取消边界。

默认模型/检索 GPU，后台 CPU/GPU 切换保持。科研绘图使用 CPU 沙箱；不开放任意宿主 shell、联网或运行期安装。工作区不挂载服务源码、密钥、数据库或全账号文件。

## 7. 完整实施顺序

1. **P0 隔离基线**：在独立 worktree/分支保留 CitrusQA_Local 当前完整服务源码和必要测试，记录一致快照，不覆盖另一会话、不提交或推送。
2. **P1 资产与复用**：建立能力保留映射、两层脚本、工作区接口、先保存后执行、引用与生命周期、失败记录和预算；完成纯整理和跨轮修改闭环。
3. **P2 技能与绘图**：接入通用技能目录；默认安装并适配 Nature 绘图核心/美学/可执行检查；研究意图与已有选择式澄清接入；保留多图、组合图和编辑重放。
4. **P3 按需交付**：能力与场景分离，默认文字；计算与发布解耦；六个导出入口合一；完成判定识别实际成果，资料库与聊天统一导出。
5. **P4 方法与环境**：共享审查和统计方法，打包实际依赖/辅助代码并记录版本；详细技能按需读取；更新文档和全部能力映射，不追求工具数本身。
6. **P5 集成验收**：精确集成另一绘图会话的稳定增量，跑隔离工程回归、真实沙箱、多轮与浏览器验收；分开报告已验证与受环境阻塞部分。

## 8. 验收与论文边界

工程验收覆盖：原有能力保留；内置复用；纯整理不产生附件；跨轮读回/patch/换数据；多图/子图及部分失败；取消与有限修复；期限清理与依赖保护；越权和版本冲突；技能来源/摘要/资源边界；Nature helper 与检查实际运行；普通问答不导出；明确格式正常交付；下载不触发模型；历史图件/Word/候选检索兼容。

使用临时数据根与新工程材料，不覆盖历史实验。真实模型 smoke 需检查工具轨迹，不能用单元测试声称 LLM 已学会复用。浏览器仅启动独立实例，不重启现有服务；启动后提供可复制网址。远程 Linux 未真实验证时明确说明。

论文四项主张保持：Claim 1 领域知识基础；Claim 2 候选获取与动态编排；Claim 3 可组合科研元能力；Claim 4 约束执行与可检查交付。场景是能力组合，文件生成是按需交付，并非每个场景的成功条件。

原 E1–E8 不重命名：E1 跨语言检索（200 锚点/配置）；E2 候选机制消融（建议100–160题、原四条件）；E3 160题 Direct/Fixed-RAG/Agent；E4 240题工具与来源；E5 12模拟工作簿及真实材料；E6 80条文献核验；E7 建议12绘图任务；E8 12复合工作流。工程回归不是科学效果证据。
