# 主 Agent 的失败观察与同轮修正

工具调用是动作提议。主 Agent 在同一真实用户轮内读取观察、修正参数并继续，不因参数拒绝启动第二个执行循环、终答模型或新的预算。

## 派发前

统一 runner 按代码拥有的实时 schema 检查参数名、必填项、类型、枚举和范围，保留原参数，不隐式转换或补值。拒绝返回 `not_run/invalid_tool_arguments`，并具体说明错误字段和合法参数。科研适配器的额外纯校验也应返回明确拒绝；不能把错误文字本身当作“没有副作用”的证据。

工具引用不可混用。`file_id`、原生 `tool_call_id`、`operation_id`、`audit_id`、`review_id`、dataset/analysis 引用分别按其返回契约使用。长结果首交保留小型执行、覆盖、终态、下一动作和导出引用；完整原文仍在权威存储，按引用分页读取，不为取回结果重新扫描。

## 输出截断

无法解析的原生工具参数先作为 `not_run/invalid_tool_arguments` 观察退回本主循环；这类提案不执行，也不以原样请求重试。`finish_reason=length/max_tokens/max_output_tokens` 的响应同样不能触发工具。Harness 将原响应保存在私有加密执行检查点中，保留 provider 私有协议状态；活动视图移除不可执行的半截参数，每个可配对原生调用收到 `not_run/model_length` 观察，然后回到同一个主模型。

第一次请求沿用 `MAX_TOKENS`。截断后允许下一次请求的输出预留翻倍，上限由 `AGENT_MAX_OUTPUT_TOKENS` / `agent.max_output_tokens` 控制，默认 16384。额度随宿主状态持久化；真实上下文准入、累计 token、调用次数、取消和原截止时间照常生效。达到单次输出上限或任务预算时如实停止。提示词同时要求精简答复、分步写入长脚本和复用已有结果，不能只靠增加输出长度。

## 执行结果

已知的未执行拒绝允许同轮修正。执行过的写操作若超时、取消或缺少可核对结果，保持 `unknown/write_requires_reconciliation`，不自动重放。只有代码拥有的适配器私有证据可以证明已知失败；模型可见的状态字段不能充当安全豁免。

活动上下文投影识别宿主添加的 `execution_dispatched` 和 `first_delivery_reference`。这些元数据不单独阻止工具组压缩；用户原始指令、已加载必需方法、完整调用/结果配对和 provider 私有协议保护继续有效。原文验证落盘后才生成导航摘要，摘要不代替证据。

## 检索推理资源

候选数量不直接决定单次 ONNX 推理批量。reranker 按 `RERANK_BATCH_SIZE` / `retrieval.rerank_batch_size`（默认 4，范围 1–32）分批评分全部候选，再进行一次全局排序；不以丢弃候选降低内存，也不改变每条文本的原长度上限。已使用 CPU 的会话失败后不重复装载同一 CPU 模型。GPU 严格模式失败仍保持不可用，不冒充 CPU 回退成功。

## 终态

`pending_tool_calls` 只表示协议尾部待处理，不证明已经执行。终态根据实际派发和观察判断是否需要对账；保留具体的调用次数、累计用量、时间或上下文停止原因。部分结果只提供真实操作统计和所有者/哈希核对过的实际下载链接，不把截断答复补成科学结论，也不把文件存在当作整项任务完成。

文献或数据审查的处理完成、来源覆盖完整、人工复核要求、可导出状态分别呈现。已处理完且无 pending/retryable 的文献审查可带复核限制导出；重复联网不能解决原始解析歧义。数据审查使用同一 `review_id` 的真实扫描结果组合 XLSX、HTML 和 JSON 交付。
