# 逐条文献核验

## 适用条件

核验用户提供的文献身份、DOI/题名/作者/年份冲突，或补验尚未覆盖的记录时使用。使用现有 `verify_uploaded_references` 与结果读取工具；不把检索候选直接标为核验成功。

## 输入要求

授权附件及其 hash/版本、完整文献条目、稳定记录身份、需要核验的规则、网络授权和已有 `rows`/`counts`/`coverage`/结果引用。无 DOI 条目需要完整题名等可识别字段；自动提取 DOI 仅覆盖识别出的条目，不代表全部参考文献。

## 方法顺序

1. 明确目标记录清单和来源版本。用实际来源标识、记录 ID 与核验规则追踪覆盖；旧回执缺少身份时标为未知，不根据条数补造记录 ID。
2. 复用已有有效结果，只补未核或有新依据可恢复的记录。调用 `verify_uploaded_references` 沿现有 DOI、登记库、授权网页回退执行。`allow_web` 服从请求授权；任何自然语言题名检索遵守母语转英文前置，精确 DOI 不改写。
3. 按返回的真实逐条状态区分已匹配、字段冲突、候选、未查到、网络失败、未核等；保留来源 URL 和证据引用。登记库身份存在不能证明论点，未查到或网络失败不能判伪造。
4. `batch_size` 仅调整并行批次；修改它、`max_rows` 或 `publish` 不创建新覆盖。分页依据本工具实际选择顺序、`start_index`、selected 数与已处理记录，不能假定任意输入顺序；超过单次选择上限时按未覆盖原记录拆分提交，保留原身份。
5. `selected=0` 时检查范围耗尽、偏移或输入，不再重复空批次。读回大结果使用 `read_tool_result` 的 JSON Pointer 字段，如 `/rows`、`/counts`、`/coverage`，按实际续读信息分页；结果截断、过期或缺失不得从摘要重造。
6. 汇总时按稳定记录去重，比较全部目标与实际已核对象。只为用户明确的文件需求发布核验表，优先复用现有结果引用；导出成功不是又核验了一批。

## 验收条件

每个目标记录有真实核验状态、依据与规则；只有真实已核记录增加覆盖。未核、失败、仍仅候选和身份不明的记录逐类保留；部分完成必须说明剩余对象、原因与可恢复动作。不能把 `counts` 总数、重复批次或工具级 complete 当成全部目标核验完成。
