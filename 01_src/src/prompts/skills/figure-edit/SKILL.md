# 已有图件按用户意图编辑

## 适用条件

用户对已有图件修改颜色、标记/图标、字号、字重、图例、文本、位置或可见性，包括自然语言修改和工作台手动操作。后续用户审美不受 Nature 美学限制；不能以 Nature 配色、字号或布局要求拒绝、回退或覆盖用户选择。

## 输入要求

实际项目、命名图件及版本，当前 manifest/gid/支持属性、已有 overrides、用户意图、源脚本或 spec 引用及初始 Nature 审计回执。目标或属性不可确定时只询问影响执行的选择；颜色、布局等已明确时直接按用户要求处理。

## 方法顺序

1. 从已有项目和 manifest 识别真实对象，保留数据、来源版本、脚本引用与稳定身份。不能根据截图或散文编造 gid，也不能假装所有 Artist 都支持编辑。
2. 将用户要求变成现有协议支持的局部 overrides，沿工作台/既有服务的预览和保存链路执行；技能不新增编辑工具或直接写宿主文件。自然语言需改脚本时通过 `research_workspace` 读取、patch 派生版本，复用原数据并在现有隔离工具执行，不从摘要重造脚本和数值。
3. 多系列共享图例时依据 manifest 的关联对象保持标记与图例一致。隐藏点或对象要如实说明呈现变化；不能把隐藏后的视图称为全部原数据。改变数值、误差、统计方法或数据来源属于新的科学操作，另建来源版本并按初始图件方法处理。
4. 局部预览、尚待服务端校正、正式保存和最终导出分别陈述。执行与保存保留现有归属、版本、文件完整性和数据真实性校验；这些校验不赋予系统替用户决定审美的权力。
5. 原样保留初始 Nature 审计事实，另记录后续用户编辑及当前导出状态。后续审美修改不重新套 Nature 约束，不把原始通过改成失败；没有初始审计的旧图标为历史/未知，不伪造补通过。

## 冻结结果和当前保存

先 `research_workspace(operation="figure_inspect", figure_id=...)`，依据实际 editable、manifest 和 render_version 提交 `figure_edit`。自然语言与画布共用 overrides/CAS 保存。网格、误差棒端帽、色条和柱填充/边框等仅使用 manifest 公布的属性；颜色和字号不应触发统计或随机过程重算。无冻结分析/独立渲染凭证的旧混写脚本仍可下载，不可静默重跑后声称仅修改样式。

项目仅保留原始脚本、必要的冻结数据、当前 overrides 和当前导出，不提供历史版本列表、历史下载或恢复。`render_version` / `expected_revision` 仅用于并发冲突检查，不是可恢复历史。工作台修改作用于脚本生成的真实 Figure/Artist：位置用坐标偏移，颜色、线宽、字体等用对应属性，然后统一重绘。原始脚本不因样式编辑改写；确实需要改渲染代码时由同一 Agent 读取源码、修改、运行、检查结果，不新设绘图循环。只使用真实返回的下载地址；初始审核仅证明原始产物，不冒称当前图件已重审。

## 验收条件

目标与属性来自真实 manifest，编辑符合用户意图，草稿/保存/导出状态有实际回执。后续导出说明“初始 Nature 审计 + 后续用户编辑”的事实，不能把初始通过冒充当前版本全部通过 Nature。用户满意的审美变化不因初始规范而被阻断。
